# M27 — Balance from player feedback (2026-10-15)

Source: feedback from a contributor (paraphrased): leveling above 5 is too slow, non-fight classes level
much slower than [Warrior], consolidation at level 10 is grindy, selling 10 goods takes 10x as long as
one, and one trip to Invrisil makes Liscor forget you. The user picked all four fixes (2026-10-15).
All numbers are game balance (`confidence: guess`), not canon. Branch `feat/m27-balance-feedback`.
One commit per step, one PR.

## M27.0 Leveling pace (data)
- `rules.levels`: `base_xp` 40 -> 30, `growth` 1.25 -> 1.2. Keep `late_from` 10, `late_growth` 1.12.
  Level 10 costs 624 XP in all (was 1032). Total level 25: ~6,400 (was ~12,100).
- `rules.xp.novelty` (the repeat penalty): `floor` 0.1 -> 0.3, `k` 0.35 -> 0.2. Non-fight work that
  repeats loses less XP. Fights keep their danger bonus.
- Tests: `unit_xp` (reads live rules; update the expected numbers), `unit_levels`, `unit_actions`,
  `sim_balance_progress` and `sim_balance_fighter` (retune the night targets to the new pace),
  `sim_30_days`, `sim_breakthrough_probe`.

## M27.1 Consolidation at level 5 (data)
- `rules.offers.consolidation_min_level` 10 -> 5. The default in `ClassSystem.consolidation_min_level`
  goes to 5 too. DESIGN §"Consolidation" text says level 10: change it.
- The Inkar example from the feedback is after Book 1 and not checked in the book text. Not used as canon.
- Tests: `unit_class_system` (the consolidation test uses level 10; move it to 5, add "level 4 is not
  enough"), `unit_class_tree_step2`, `unit_class_tree_step4`.

## M27.2 Buy and sell many at once (core + UI)
- `Economy.buy/sell(gs, db, object_id, good, count := 1)`, `Commands.buy/sell` pass `count` on.
  - Sell: `count` is clamped to what is in the bag. Buy: the player must afford all; else an error.
  - A meal eaten where bought (`eat_now`) or worn clothes (`wear_flag`): count is always 1.
  - Time: `trade_minutes + trade_extra_minutes x (count - 1)`. New optional key
    `rules.economy.trade_extra_minutes` = 1 (missing = 0). 10 goods = 14 minutes (was 50).
  - One action record for the whole trade, so the repeat penalty counts it once.
  - One line: "You sell 10 blue fruit for 2 silver."
- Use-menu ids: `buy:<good>` / `sell:<good>` stay; a count goes after `#` (`sell:herbs#10`).
  `Interact.trade_action(kind, good, count)` builds one, `Interact.trade_parts(id)` reads one.
- `Economy.trades` adds `"have"` (bag count) to sell rows. Use menu (`ui/interact_menu.gd`): a sell row
  with more than one in the bag also gets "Sell all N x (total)". A bag good (not eat_now / wear_flag)
  also gets "Buy 5 x (total)" (`rules.economy.bulk_buy` = 5, missing = no row).
- Console: `buy|sell <object> <good> [count]`.
- `world/main.gd` reads the count with `Interact.trade_parts`. Sound cues still match the `buy:` /
  `sell:` prefix.
- Tests: `unit_economy` (new: sell many takes 5 + 1 x (n-1) minutes, one record, clamp to bag, buy many
  needs all coins, eat_now is one), `unit_interact`, `unit_sound_cues`, `sim_celum_trip`.
- Schema: two optional keys in `rules.economy` (user approved the feature 2026-10-15). No save change.

## M27.3 Slower forgetting (data)
- `rules.standing`: `decay_after_days` 7 -> 30, `reputation_decay_every` 3 -> 10.
  A 14-day trip to Invrisil now costs no relationship points; reputation loses about 1.
- Tests: `unit_standing` (check it does not hard-code 7 or 3), `unit_night`.
